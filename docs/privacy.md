# 数据流与公开边界

消息读取发生在部署者自己的 Windows 电脑。微信接口读本机数据和当前进程可取得的密钥，维护解密缓存；QQ 接口复用当前 QQ 登录。项目没有新增云端消息存储。

AI 客户端会把选取的消息和工具结果放入所选模型的上下文；客户端会话记录也可能保留这些结果。是否使用云端模型、选择哪家提供方，由部署者自己决定。避免为了普通问题把整个历史全文反复写入工具输出，按任务筛选时间和会话。

私有 deployment.json 保存机器路径，不需要模型 API key。QQ accessToken 和微信密钥由请求代码在进程内部读取，不粘贴进提示词、URL 或命令行。新安装默认私有根目录是 `%USERPROFILE%/.local/share/wechat-qq-access`，旧 AppData 配置保持兼容；定位顺序与选中失败不回退的规则见 [部署配置](deployment.md)。不要将私有根目录放入同步或公开仓库。

统一读取入口在代码中按平台、账号和稳定会话 ID 检查白名单／排除名单；面板与共享 skill 共用这一处权限实现。上游库与 QQ token 自身仍可能具备其他能力，因此必须通过该入口访问；同一 Windows 用户下拥有完整命令权限的其他程序不属于此隔离边界。登录和必要的界面操作由用户完成，项目脚本不使用 GUI 自动化。

微信上游会解密整个消息分片，分片可能包含多个会话；这些文件留在受信读取端。产品限制的是对会话的查询、返回及模型外发，不宣称底层从未接触被禁会话的字节。模型任务只收到经过授权的文本，不持有原始库、密钥或 token。

QQ 的网络边界另见 [QQ 说明](qq.md#网络边界)：虽然请求使用回环地址，固定上游版本仍监听所有网卡，私有接口靠 token 加真实来源 IP 白名单保护。安装时必须明确接受公开元数据端点的局域网可达性；不要将端口映射到互联网。

公共发布使用显式文件范围，排除 vendor、虚拟环境、实际配置、私人证据、聊天库、日志、媒体和导出。`.gitignore` 是辅助边界，不能代替发布前检查。`scripts/prepare-release.ps1` 构造独立候选目录并检查常见机器路径与意外凭据，发布者仍须审阅实际文件清单。
