# 运行数据与清理

本项目关注运行数据随使用增长的控制，程序本体按完整安装保留。没有设置后台清理服务或统一磁盘配额。

| 类型 | 增长方式 | 保留／清理方式 |
|---|---|---|
| 微信解密缓存 | 固定文件名复用；原消息库增长会使副本增长 | 可重建，按需清理；下次读取需微信保持登录和可用密钥 |
| 微信刷新临时文件 | 分片刷新时短暂生成；异常可能残留 | 已过保留时间的已识别临时文件可清理 |
| 图片等媒体副本 | 按需提取不同文件时增长 | 默认保留，明确选择媒体类别再清理 |
| 完整历史快照 | 主动导出时产生 | 不在普通查询中滚动生成；需保留的成果另行存档 |
| QQ 消息 fetch 缓存 | 主要在有界内存中 | 关闭服务即释放，不另复制聊天数据库 |
| 日志 | NapCat 有轮转，部分 QCE 日志可持续增长 | 清理过旧日志，运行中的 QQ 日志跳过 |
| 原始聊天库与密钥 | 原客户端维护／少量固定缓存 | 清理工具保留，不作为腾空间对象 |
| AI 客户端对话历史 | 保存提示词、工具输出和模型结果 | 使用相应客户端的会话管理，本工具不触碰 |

微信当前版本在源 DB 或 WAL 变化时会重建对应解密分片；旧缓存、解密临时和 WAL 合并临时可能同时存在，所以刷新有短时空间峰值。正常完成后替换旧缓存。普通提问不会永久保存一份新的完整库。

## 常用命令

在项目根目录使用 PowerShell 7：

```powershell
# 只看占用、可清理计数与跳过情况
.\scripts\cache.ps1

# 先预演，再按相同条件实际清理
.\scripts\cache.ps1 -Action Clean -Category WeChatCache -OlderThanDays 7 -WhatIf
.\scripts\cache.ps1 -Action Clean -Category WeChatCache -OlderThanDays 7

# 旧日志
.\scripts\cache.ps1 -Action Clean -Category Logs -OlderThanDays 14 -WhatIf

# 明确不再需要的媒体副本，先预演
.\scripts\cache.ps1 -Action Clean -Category WeChatMedia -OlderThanDays 30 -WhatIf
```

完整快照另用 `Snapshots` 类别明确选择；不要把需要保留的唯一导出当作临时缓存。`All` 的具体覆盖以脚本帮助为准。清理有最小文件年龄，近期、使用中或无法验证的文件会跳过。先结束本次 AI 读取；QQ 日志在 QQ 接入运行时跳过，正常退出后再清。

确需立即清空当前缓存时，先结束 AI 读取命令，再显式使用 `-OlderThanDays 0` 预演和执行；这会取消年龄保留，但仍跳过活动读取、锁定文件、密钥和未知文件。默认七天条件保持不变。`All` 清理只包括微信缓存和本部署日志，媒体与快照仍需明确选择。

工具只枚举验证过的目录中的已识别普通文件，跳过目录链接／重解析路径，并按准确文件逐个移入 Windows 系统回收站。所有密钥、实际配置、未知文件、程序本体和原始微信／QQ 数据保留。回收失败时保留文件，不回退永久删除。日志中的 RemovedBytes 表示离开原目录的字节，ReclaimedBytes 为零；回收不等于实际释放磁盘空间，本工具不清空回收站。日志留在本机私有目录，不要上传。

QQ 清理仅覆盖本项目运行目录中的日志；共享的 `%USERPROFILE%/.qq-chat-exporter`、旧 Documents 导出目录等不自动清理，避免影响其他部署。

若缓存清空后无法重新读取，应先检查微信是否正常登录、密钥和兼容版本是否可用；不要删除密钥作为修复手段。QQ 媒体默认不批量下载，已有外部导出目录不由本工具猜测位置或自动清理。
